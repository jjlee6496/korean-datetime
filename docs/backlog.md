# 백로그

결정이 필요하거나 아직 하지 않은 일. 수치는 AI허브 「시간 표현 탐지 데이터」 Validation(개발용) 기준이고,
Training은 최종 확인용으로 남겨 둡니다.

## A. 대화 데이터 실패 분석 (2026-10-02)

대상: Validation 대화 2,411문서, 정답 표현 11,717개. 놓침 3,793 / 값 틀림 78(값 비교 819 중) / 오탐 420.

### A1. 평가 스크립트: 범위 끝 정답을 범위 시작과 비교함

- 원인: `scripts/aihub_eval.py`가 정답과 겹친 첫 예측의 시작 값만 비교. "10월 19일부터 21일까지"의 "21일" 정답이
  범위 시작(19일)과 비교돼 틀림 처리 (34건). `compare_libraries.py`에만 범위 끝 처리(`_candidates`)가 있음
- 월 단위 정답 7건 중 2건은 달력 줄 주차 정책("10월 마지막주 금요일" → 11/4), 5건은 정답 문맥 문제
- 계획: 범위 끝 비교를 `aihub_eval.py`로 옮기고 두 스크립트가 공유. 벤치마크 문서 재생성.
  대화 값 정확도 0.905 → 약 0.946 예상 (파서 변화 없음, 측정 보정)

### A2. 붙여 쓴 시간대 ("점심시간에", "아침마다", "밤늦게")

- 원인: 시간대 말 뒤에 조사가 아닌 한글이 붙으면 다른 낱말로 보고 버림 ('밤나무', '아침이슬' 오탐 방지)
- 데이터: 정답에 표시된 붙여 쓰기 - 시간(31), 마다(29), 때(15), 일찍·늦게·새(22).
  표시 안 된 쪽은 먹·식사·밥(25+, 식사의 뜻)
- 계획: 뒤에 오는 말 허용 목록(시간·마다·때·일찍·늦게·새·무렵·내내). 먹·식사·밥은 계속 막음.
  예상 검출 +60~80
- 결정 필요: 일정 챗봇에서 "점심먹고 보자"를 시간으로 볼지

### A3. 계절 (가을·겨울·여름·봄, 놓침 388)

- 데이터: 정답 표시 가을 161/179, 여름 131/150, 겨울 117/125, 봄 41/44. 비표시는 '가을 웜톤', '여름 쿨톤', '가을 옷' 등
- 계획: 기상청 기준 구간(봄 3~5월, 여름 6~8월, 가을 9~11월, 겨울 12~2월), 새 grain SEASON.
  수식어(올·이번·지난·다음·초·한·늦). 겨울은 해를 넘기므로 1~2월의 '이번 겨울'은 지난 12월부터.
  '웜톤·쿨톤·옷'이 뒤따르면 제외. 예상 검출 +400, 오탐 +30
- 결정 필요: 계절 구간 기준

### A4. 절기·기념일 (놓침 약 60)

- 원인 1: 띄어쓰기 변형 없음 ('화이트 데이', '빼빼로 데이'), 다른 이름 없음 ('이브날', '가갸날')
- 원인 2: 고정 기념일 누락(식목일, 국군의 날, 부부의 날). N번째 요일 기념일(청년의 날 9월 셋째 토요일,
  성년의 날 5월 셋째 월요일)은 holidays.json 형식이 지원하지 않음
- 원인 3: 24절기·복날 없음. 절기는 `lunar._solar_term_jde`로 계산 가능, 복날은 경일(庚日) 계산 필요
- 계획: 띄어쓰기 자동 변형, 고정일 추가, N번째 요일 형식 추가, 24절기 천문 계산(한국천문연구원 날짜로 검증)
- 일반 낱말과 겹치는 절기(하지·동지·대한·소설·우수·청명·백로·대서·소서)는 '날·무렵·절기'가 붙을 때만
- 개인 기념일(결혼기념일, 생일, 100일)은 외부 달력 주입으로 안내
- 결정 필요: 위험 절기 처리 방식, 복날 포함 여부
